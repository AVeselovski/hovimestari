# Barcode after a miss, fix batch (2026-11-28)

- **The inline-flex space bug came back on a flex _row_ (`foodSourceRow`'s span).** A rich label with `<digits>` read "Barcode6416…" on the own food's source row. Any `t.rich` with a tag inside a flex container needs one wrapping `<span>`. jsdom cannot see it; the owner screenshots caught it. The test pins it structurally: the mono span's parent is not the flex item (`data-own-barcode`).
- **Moving a control up a view turns its late arrival into a layout shift.** The copy button rendered only once the detail loaded. At the foot that was invisible. Under the source line it pushed Per 100 g down 89 px a frame or two after the view opened. Fix: render from the row's `source` at once, `aria-disabled` until the detail is in. Sample tops per rAF from the row tap, not only at rest.
- **A control moved into the upper half of a view is in reach of a double tap's second tap.** The log sheet's food view holds no presses after a row opens it (Planned already flips that way). Measure with a CDP touch double tap on a result row at the control's y before calling a placement done. Filed in TODO, not built (brief scope).
- **Owner decision via the orchestrator:** one copy button, after the source line, before Per 100 g, no carried special case. A rule above it (`border-t pt-4`) is kept so it reads as an action like Edit food.
- **Production web build with `backend.env` sourced (`set -a`) fails** on `/_global-error` with "reading 'useContext'", because NODE_ENV=development leaks in. Build with `env -u NODE_ENV`. Sign-in in a production build needs the `x-real-ip` header on the Playwright context.
- **`kill <npx pid>` leaves `next-server` running on the port**; the next `next start` exits and the stale server serves a mismatched `.next`. Find next-server by `pgrep` plus `/proc/<pid>/cwd` and kill that PID.
