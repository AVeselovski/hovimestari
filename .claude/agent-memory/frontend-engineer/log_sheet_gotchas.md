- **Base UI's Drawer stops catching presses as its exit starts** (`pointer-events: none` on viewport and backdrop while `open` is false). Part 1 worked around it with a close wait; part 2 fixed it in `BottomSheet`: the backdrop keeps `pointer-events: auto` through a style function and drops presses while `data-closed` (`components/ui/closingSheet.ts`). jsdom has no hit testing, so pin the backdrop's inline style and `defaultPrevented` there, and measure the double tap in Chromium with `page.touchscreen.tap` at 60, 150 and 300 ms, counting non-GET requests.
- **A mutation that changes one close path may prove nothing.** "Save and log" closes the stacked sheet from the sheet itself and from `FoodSheet`. Delaying only `FoodSheet`'s close left the test green, because the sheet closed itself in the same update. Mutate every path, and watch the parent's and the child's state together with a `MutationObserver` (attributes and childList), since a parent closed first removes a nested child with no exit.
- **TanStack notifies observers on a timer.** `await act(async () => answer(...))` then a plain `expect` passed alone and failed in the loaded full run. Wait with `waitFor` after resolving a query's promise by hand.
- **The orphan key sweep resolves a translator passed as a parameter only through a same-file alias**: `type ToastT = ReturnType<typeof useTranslations<"toast">>` and `t: ToastT`. An inline `ReturnType<…>` in an interface reads as orphaned keys.
- **A form sheet's height budget.** At 390 by 844 a tall form sheet's body is 552 px; the footer with the refusal room, a `footerStart` row and the buttons is 181 px. Every field keeps its line, so sum the blocks (label 26, input 48, line 26 or 46, gap 12, chip row 58, StateChoice 106) before promising "fits without scrolling". The measure script lived in the scratchpad (`measure-meal.mjs`): dialog, header, body, footer and each form child's top and bottom.
- **Base UI renders each toast as `role="dialog"`** (`aria-modal="false"`, `data-toast`). A probe that looks for "any dialog on screen" counts the toast. Query `[role=dialog][aria-modal=true]:not([data-toast])` for a sheet.
- **The test query client has `staleTime` 0; the app's is 30 s** (`makeQueryClient`). A test about "no request in flight after a prefetch" must give its client the app's freshness, or the mount refetches and the test lies the other way.
- **Every Playwright script that loads the app rotates the refresh cookie.** Save `storageState` at the end of every script, or the next script's session is dead (the page lands on sign-in). Keep a sign-in script with the account's password in a scratch file to recover.
- **Accessible names with units hold a no-break space** ("250 g"). `getByRole({ name: "… 250 g" })` fails on it; `findByText` and `toHaveTextContent` normalise it. Match names with a pattern where a space is `\s` (`loosely()` in `components/log/__tests__/logHarness.tsx`).
- **next-intl's typed catalog comes from `messages/en.d.json.ts`**, generated by `next typegen` (`pnpm typecheck`). After adding catalog keys, a bare `tsc` reports them missing until `pnpm typecheck` regenerates it.
- **Base UI exits await two rounds of animations in Jest** with `controlSheetAnimations`: call `finish()` until the popup is gone, asserting what must not show in between.

- **A stacked sheet is portaled, so native DOM containment misses it.** A press inside `SavedMealSheet` is not `contains`-ed by the log sheet's popup. Use React capture handlers on the popup (`onPointerDownCapture`), which hear portaled children through the React tree. The stacked sheet unmounts with its parent's exit, so anything it owns that must outlive the close belongs to the parent too.
- **`controlSheetAnimations().finish()` once is not enough under fake timers.** Base UI may call `getAnimations()` again after the first `finished` resolved and get the fresh, unresolved promise. Finish inside a `waitFor` until the state you need (`data-press-guard="armed"`) shows.
- **The emulated keyboard's inset drops on every focus move.** Overriding `visualViewport.height` sets `--drawer-keyboard-inset` for the focused field; a Tab to the next element recomputes it to 0. Measure the keyboard state right after focusing a field, and check focusability directly (`el.focus()` then `activeElement`), not by tabbing.
- **`findByRole("alert")` returns the reserved empty line at once.** Form lines keep their room, so the alert is in the DOM before its text. Wait on the text: `waitFor(() => expect(getByRole("alert")).toHaveTextContent(...))`.
- **Launcher `aria-disabled` until today is known.** A Day tab test that clicks Log food straight after `findByRole` can click it while it waits. Wait for `not.toHaveAttribute("aria-disabled")` first.
- **Run the full web suite twice at once with `--maxWorkers=8` and `6` on 4 cores** to shake out timing flakes: it found five that single runs never showed.

**Why:** each of these cost a run or a wrong conclusion in 3c parts 1 and 2.
**How to apply:** read before building or testing anything in the log sheet, or any sheet whose action closes it.

## jsdom has no PointerEvent (fix cycle 2)

`fireEvent.pointerDown(el, { clientX })` in jsdom makes a plain `Event` with no coordinates, so code that reads a press's point from `pointerdown` sees `undefined`. Browsers' `PointerEvent` is a `MouseEvent`, so a suite that needs the point defines `window.PointerEvent = class extends MouseEvent {}` in `beforeAll` (see `BottomSheet.closingPresses.test.tsx`). How to apply: any test of press position.

## Hold before you read (fix cycle 2)

A pending "+" id is freed by `forgetSeen` in the day query's `queryFn`. Anything that reads the day after an unconfirmed add must set `holdPending` first, in the same call, or the read can free the id before the caller's catch sets the hold. That is why the hold lives in `useAddActions.sendAdd`, not in `useLogAgain`.

## Phone exit vs a quick press (fix cycle 2)

At 390 a stacked sheet's exit lasts about 420 ms, and its backdrop drops every press until then by design. A browser check that presses the parent sooner than that fails for that reason, not the window swallow. Measure the exit end (the popup leaving the DOM) before blaming `useClosingPresses`.

## Open lists and reads (fix cycle 3)

- **`useSheetTarget().shown` never goes back to null** (`useRetainedValue`). "Is a stacked sheet on screen" is `isOpen`, not `shown !== null`; `shown` stays set for the rest of the parent's open.
- **A read whose abort signal was taken is cancelled and reverted when its last observer unmounts.** A prefetch started as the log sheet closes died with the closing sheet's lists, even from `onClosed` (it fires before the popup unmounts). Reads meant to outlive the sheet pass a `queryFn` without the signal (`prefetchLogLists`).
- **A cache edit reaches observers on TanStack's timer.** Anything that must act after observers saw an edit (`releaseHeldLists`) goes through `notifyManager.schedule`.
- **The env files beat the process environment here.** `next build` baked `.env.local`'s API URL over `NEXT_PUBLIC_API_URL` from the shell, and backend CORS came from `.env`. For a browser check on other ports, back up and edit both files, restore after. Also look for leftover `tsx watch` backends on the port before blaming the app: one from an earlier cycle answered for a whole run (`kill -9`, they ignore SIGTERM).

**Why:** each cost a wrong run in fix cycle 3. **How to apply:** before a browser check, and before any code that reads "is a stacked sheet up" or prefetches as a sheet closes.
