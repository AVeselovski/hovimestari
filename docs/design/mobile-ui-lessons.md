# Mobile UI lessons from finanssi

Architect's research note, 2026-11-14. Source: the `finanssiappisV2` repository (called finanssi below), read at `/home/user/finanssiappisv2`. Every finanssi path below is relative to that repository. Where this note recommends something finanssi's own docs do not say, it says so.

## Purpose

Read this before the scaffold's design doc and before every UI step after it. It is for the architect and the frontend-engineer. Finanssi took about four months and many owner round trips on an iPhone to make its web app feel right on a phone. Artur's instruction for Hovimestari is to start where finanssi ended: proper UI primitives for sheets, dialogs and pickers from day one, and the conventions finanssi learned the hard way. This note is the short version of what it learned, with pointers to the long version.

## How finanssi got here, in one paragraph

Finanssi started with hand-rolled overlays: a centred modal per form (`modalPanel` plus `stickyModalFooter`), a hand-built `BottomSheet` and a hand-built nav drawer with a `setTimeout` unmount. Three "mobile-responsive" rounds in July 2026 fixed layout found on the owner's phone (`docs/design/mobile-responsive-step0*.md`, `mobile-responsive-round3.md`). On 2026-09-22 an assessment adopted `@base-ui/react` 1.8.0, but only for popovers, menus and info icons, and recommended keeping the dialogs, the sheet and the nav drawer custom (`docs/design/component-library-adoption.md` §3, §11). Six days later every overlay was on Base UI: the owner wanted the "finished", tactile feel of a swipeable sheet on every task overlay, and Stage 4 moved `BottomSheet`, all form dialogs, `ConfirmDialog` and the nav drawer onto Base UI's `Drawer` (`docs/design/mobile-sheets-stage-4.md`, S1 to S8, 2026-09-25 to 09-28). Polish on top of the library then ran into late October (lost taps under the keyboard, 2026-10-29). Finanssi's docs contain no explicit "if we started again" section. The history itself is the lesson: the "keep custom" calls were reversed within a week, and the hand-built overlays produced most of the early bugs.

## What finanssi learned, in one page

1. **Use the library primitive for every overlay from the start.** Symptom: the hand-rolled `HeaderBalanceDropdown` rendered 150px off the left edge of a 375px phone (`absolute right-0` against a pill whose alignment flipped with width). `BalanceAlert` and `InfoTooltip` were hover-only CSS tooltips, so on the phone their content never rendered. The hand-built drawer had no animation and needed a `mounted`/`visible` state pair. Fix: Base UI `Popover` (with `openOnHover` for info icons), `Menu` and `Drawer`. Sources: `docs/design/mobile-responsive-round3.md` Finding 2, `docs/design/component-library-adoption.md` §5 and §11, `.claude/agent-memory/architect/project_mobile_header_positioning_risk.md`.

2. **There is no hover on a phone. Never use a tooltip.** Base UI, Radix and React Aria all disable `role="tooltip"` on touch by design. Fix: an info icon is a button that opens a `Popover` with `openOnHover` on the trigger. The same blindness hits hover-only affordances: a tappable name that looks like plain text until hovered tells a phone user nothing (open in finanssi `TODO.md`). Source: `component-library-adoption.md` §5, `.claude/agent-memory/architect/project_component_library_assessment.md`.

3. **A Base UI Drawer animates only if it mounts closed, and only if it stays mounted.** Symptom: sheets appeared and vanished with no motion. Cause: Base UI plays no entry for a root that mounts already open, and an unmounted sheet has nothing to animate out. Fix: `BottomSheet` mounts its root closed and opens in a layout effect. Callers keep it mounted, drive `open`, and keep its content with `useRetainedValue` while it slides out. A reopen during the exit reuses the old children, so mount-time focus logic does not rerun. `BottomSheet` remounts its body under a per-open key. Sources: `mobile-sheets-stage-4.md` §2.1, `.claude/agent-memory/reviewer/feedback_drawer_reopen_during_exit.md`, `.claude/agent-memory/frontend-engineer/patterns.md` "BottomSheet on Base UI Drawer".

4. **Lock the element that actually scrolls.** Finanssi's shell is `h-dvh` with `<main>` as the only scroll container. Base UI's own lock targets `<html>`/`<body>` and on iOS only sets `overflow: hidden`. So every Drawer runs `modal="trap-focus"` and the app locks `<main>` itself, restoring `overflow` and the exact `scrollTop`. The lock is counted, because a nav drawer and a sheet can open and close in either order. Source: `apps/web/src/hooks/useMainScrollLock.ts`, `mobile-sheets-stage-4.md` §3.

5. **A form sheet with input refuses every dismissal and springs back.** A swipe down on a form scrolled to the top is also how you scroll up, so it is the easiest accidental close. Fix: `dismissible={!dirty && !saving}`. Escape, backdrop and swipe call `details.cancel()` in `onOpenChange`, and Base UI plays the sheet back to rest. Cancel always closes. Trap: on Android the refusal works once. Base UI's `CloseWatcher` is spent and the second back gesture navigates. Sources: `mobile-sheets-stage-4.md` §0 D3 and §2.3, `.claude/agent-memory/reviewer/feedback_base_ui_closewatcher_consumed.md`.

6. **On a phone, never focus a text field as a sheet opens.** Symptoms: the keyboard popped while the sheet was still sliding, and a date input focused mid-slide opened the iOS date picker full screen over the sheet. Fix: on a phone the sheet's body takes focus (`PromptSheetBody`) and the keyboard comes up on the user's tap. From `md` up the first field autofocuses. Sources: `patterns.md` "Kept-mounted sheets" (S2 fix round), `docs/app/mobile-responsive-shell.md` "Bottom sheets".

7. **The iOS keyboard needs the library's keyboard handling, then a fix on top of it.** Base UI's `Drawer.VirtualKeyboardProvider` keeps the focused field in view and exposes `--drawer-keyboard-inset`, which the footer's padding adds, so Save rides above the keyboard. It also smooth-scrolls the body on every focus change and every visual viewport change, and resolves a tap at the point the finger lifts. Symptom: "tap Payee, focus stays on Amount", 12 of 20 taps lost in an emulated run. Fix: `useStillUnderFinger` holds the body still while a finger is down. A side effect: the provider cancels the touch's default, so no `mousedown` fires, and a combobox that closes on document `mousedown` stays open (open in finanssi `TODO.md`). Close on `pointerdown` or `focusout` instead. Sources: `.claude/agent-memory/frontend-engineer/phone_sheet_taps.md`, `apps/web/src/hooks/useStillUnderFinger.ts`.

8. **Double taps land on whatever slid in under the finger.** Symptoms: the second tap of a double tap on an opener closed the sheet it had just opened, or hit the entering sheet's Delete, or opened the drawer's vault switcher. Fix, in layers: an outside press is refused until the Drawer reports it is at rest (`useEntryPressGuard`). A consequential action (confirm, delete) arms only after `onOpened`, at least 500ms after open, and only for a press that started armed (`useArmedAtRest`). All three conditions are needed, because a touch on an entering sheet ends its entry at once. Sources: `.claude/agent-memory/reviewer/feedback_sheet_footer_under_opener_finger.md`, `apps/web/src/hooks/useArmedAtRest.ts`, `patterns.md` S5 and S8 review rounds.

9. **Focus return needs an explicit target on iOS.** WebKit never focuses a tapped button, so "capture the focused element at open" captures `<body>`. Base UI's `finalFocus` runs only after the exit animation. Fix: `finalFocus={false}`, the sheet restores focus itself the moment `open` goes false, and every opener passes `returnFocusTo={event.currentTarget}`. A sheet-to-sheet handoff in one update hops focus through the old opener first, so log every `focusin`, not the final `activeElement`. Sources: `.claude/agent-memory/reviewer/feedback_sheet_handoff_focus_hop.md`, `patterns.md` "Floating Add button".

10. **Stacked sheets nest by React tree, and the parent must never close alone.** A `BottomSheet` rendered in the parent's `stacked` slot is a nested Drawer. The receding parent is CSS you write from Base UI's variables. If the parent closes while its child is open, the child vanishes with no exit and no `onClose`, and focus lands on `<body>`. Sources: `.claude/agent-memory/architect/project_mobile_sheets_stage4.md`, `.claude/agent-memory/reviewer/feedback_stacked_sheet_parent_closes_first.md`.

11. **Inputs: 16px text, text inputs for numbers, native pickers.** iOS Safari zooms on focus under 16px, so `inputClass` is `text-base`. `type="number"` rejects the comma a Finnish keypad types, so a fractional amount could not be entered at all. Fix: `type="text"` with `inputMode`, and one shared parser that accepts `,` or `.`. Dates are native `<input type="date">`. On the owner's iPhone the date input still rendered 382px wide in a 356px slot, because real iOS Safari sizes it from its intrinsic width. `-webkit-min-logical-width: 0` did not help on his Safari, though the sandbox WebKit said it did. The fix that stuck is `appearance: none` under `@media (pointer: coarse)` only, because on desktop Chrome it strips the picker affordance. Sources: `docs/design/mobile-amount-input.md`, `apps/web/src/app/globals.css` (the `input[type="date"]` block and its comment), `patterns.md` "Invisible-native-date".

12. **Native controls on touch is an owner rule, not a preference.** Artur trusts the platform's pickers over anything the app builds. A custom select, calendar or date picker on touch is rejected. The iOS date picker opening over a sheet is expected. Sources: `.claude/agent-memory/architect/project_native_on_mobile_directive.md`. Hovimestari's `CLAUDE.md` already carries this rule.

13. **Pin the footer outside the scroll body, never with sticky tricks.** The old `stickyModalFooter` used `-mb-6` on a sticky element. That permanently clipped the last 7.7px of content. A keyboard resize then left `scrollTop` stale, stranding the focused field below the visible panel. Both went away when the footer moved outside the scrolling body inside the Drawer. Sources: `docs/design/modal-sticky-footer-scroll.md`, `mobile-sheets-stage-4.md` §d.2.

14. **One breakpoint, and choose layouts with CSS, not JavaScript.** Finanssi uses `md` (768px) for the whole shell. What must look different at first paint is mounted twice and shown with `hidden md:block` / `md:hidden`, because a JavaScript viewport read paints the wrong copy for a frame. `useIsMobile` is only for values CSS cannot express and for choosing between two overlays that are never open at first paint. jsdom has no `matchMedia` at all, so a global stub in the test setup is required. Sources: `docs/app/mobile-responsive-shell.md` "Layout", `patterns.md` "BottomSheet primitive + PeriodSelector".

15. **Playwright does not show the bugs that matter most on a phone.** Neither Playwright engine renders a software keyboard. `setViewportSize` shrinks `innerHeight` too, so Base UI never sees a keyboard. Headless WebKit renders no backdrop blur and ignores `min-height` on a native `<select>`. A swipe test helper moving 1px/ms passed "past half closes" on flick speed, not distance. Sources: `phone_sheet_taps.md`, `.claude/agent-memory/reviewer/feedback_base_ui_swipe_helper_timing.md`, `patterns.md` S1, S7 and S8 notes.

## Conventions to carry over

- **One shell breakpoint, `md`.** Below it is the phone presentation. Below `md`, every dialog is a bottom sheet. A different place or look per width means two mounts switched by CSS (`hidden md:*` / `md:hidden`), never a JavaScript viewport read. A different size is `md:` classes on one component.
- **`useIsMobile` only where CSS cannot do it:** a value for JavaScript, a widget the phone never mounts, or the choice between a popover and a sheet that opens on a tap. Never for content visible at first paint.
- **Every task overlay on a phone is a `BottomSheet`.** Title fixed at the top, actions fixed at the bottom, body scrolls between. On a phone the actions are two equal 44px buttons side by side. The handle is visible below `md` only. The sheet stands at least 14rem tall. No snap points.
- **Sheets stay mounted.** Callers render `{shown && <Sheet key={shown.key} open={target !== null} />}` with `useRetainedValue`, and each open gets a fresh key.
- **Dismissal.** Escape, a backdrop tap and a swipe close a clean sheet. A dirty or saving form refuses all three and springs back. Cancel always closes. On a confirmation, only the action button confirms, and focus opens on Cancel.
- **Focus.** On a phone no text field takes focus as a sheet opens. From `md` up the first field does. Every opener passes `returnFocusTo`. A focus ring shows only after a keyboard close (`lib/lastInputModality.ts`).
- **Entry guards.** Outside presses are refused until the sheet is at rest. Consequential actions arm with `useArmedAtRest`. Measure double taps in both directions of a handoff.
- **Keyboard.** Every form sheet passes `keyboardAware`. Its footer adds `var(--drawer-keyboard-inset, 0px)` to its padding. Submit buttons sit in the footer, outside the `<form>`, and reach it with the `form` attribute so Enter still submits.
- **Touch targets.** Below `md`, any control a thumb must hit is at least 44 by 44 (`touchTarget` in finanssi's `styles.ts`). A control that must not grow gets an invisible 44px hit area instead (`touchHitArea`). Neighbours sit outside its reach.
- **Fields.** Text is 16px. Numbers are `type="text"` with `inputMode`. Dates and selects are native. An optional field gets a 44px clear button inside it. Validation messages are lines under the field, never the browser's bubble.
- **Busy labels keep their width** (`StableLabel`), so "Saving…" does not move Cancel.
- **One scroll container, locked by the app.** Lift finanssi's `h-dvh` shell with `<main>` as the scroller and `useMainScrollLock`, or decide differently in the scaffold design and adapt `BottomSheet`. Do not mix the two.
- **A z-index ladder in the style recipes,** not per component. Finanssi's: page, floating Add button 40, in-page click-away overlay 41 and its popup 42, nav drawer 45, sheets 50, portalled popovers 9999 (`patterns.md` "Floating Add button").
- **Nothing a user must reach lives in a table header or a last column.** Neither exists while a table is empty or on a phone. Such a control goes in the always-present header.
- **No `Tooltip` anywhere.** Info is a `Popover` with `openOnHover`.

## Real-device verification

What only an iPhone shows, from finanssi's record:

- The software keyboard: whether Save rides above it, whether the focused field stays in view, whether taps between fields land. No Playwright engine renders a keyboard (`mobile-sheets-stage-4.md` §h).
- Real Safari layout of native controls. The date overflow measured 382px on the owner's phone and 0 in the sandbox's WebKit.
- The swipe's feel and the motion (M9 in `mobile-sheets-stage-4.md` §i). The owner signed off S1 on his iPhone on 2026-09-25.
- Safe areas. Finanssi never set `viewport-fit=cover`, so every `env(safe-area-inset-*)` is 0 there. Opting in needs the header, sheets, drawer and floating button checked on a notched iPhone (finanssi `TODO.md`). An installed PWA in standalone mode makes this matter more, because the home indicator sits over the bottom tab bar.
- Third-party pickers, such as Google's Drive folder picker, and for Hovimestari the camera for barcode scanning.

How finanssi did it:

- **Owner sign-off through `ui-preview`.** Curated screenshots in chat before merge, then Artur tries the build on his phone. Every Stage 4 slice had "owner confirms on his iPhone" as an exit criterion.
- **An on-screen geometry readout.** For the date overflow, a temporary on-screen readout of the live geometry on his iPhone gave the numbers (`globals.css` comment, 2026-09-23). That is the cheapest way to measure a real device without a Mac tethered to it.
- **Sandbox approximations before the device.** Playwright WebKit at iPhone 13 size (390×664) and Chromium at 320×568, 375×667 and 390×844, both themes. Install WebKit into the scratchpad with `PLAYWRIGHT_BROWSERS_PATH`. Emulate the keyboard by overriding `visualViewport.height` on the instance and dispatching `resize` on it (numeric keypad about 260px, text about 336px). Drive touches with CDP `Input.dispatchTouchEvent`, and in WebKit with `document.createTouch` (the `Touch` constructor throws). Source: `phone_sheet_taps.md`, `patterns.md` S1.
- **A measurement protocol per sheet change** (`mobile-sheets-stage-4.md` §i, M1 to M9): rest position, sampled motion, swipe at 20%, 45% and 60% by drag and by flick, dirty-form refusal, scroll lock with `<main>` at 300, focus with every focusin logged, and across-state position checks.
- **Production builds for motion and CSS.** The long-running Turbopack dev server served a stale `globals.css` several times, so a sheet "had no animation". Check the served CSS for a rule you expect before measuring, or measure on `next build && next start`.
- **WebKit quirks to remember:** a tapped button is never focused, Tab skips links, headless renders no backdrop blur, `min-height` on a native `<select>` is ignored, and a mid-animation screenshot lands about 150ms late.

## Open questions

- **Scroll container.** Finanssi's `BottomSheet` assumes `<main>` scrolls and the document does not. With a fixed bottom tab bar in a standalone PWA, letting the document scroll and using Base UI's own lock (`modal={true}`) is a possible simplification. It is untested, and Base UI's iOS lock only sets `overflow: hidden`. The scaffold design should pick one.
- **`viewport-fit=cover` and safe areas.** Finanssi left it off. Hovimestari's tab bar and sheets in standalone mode need it decided at scaffold time and checked on Artur's notched iPhone.
- **Base UI version.** Finanssi pins 1.8.0. Whether a newer version changes the Drawer facts in lesson 3 to lesson 10 (initial-open animation, `finalFocus` timing, the `CloseWatcher` refusal) is unknown here. Re-read the package source if the scaffold upgrades.
- **Base UI `Combobox`, `Autocomplete`, `Toast` and `NumberField`.** This note did not verify that they exist in the version the scaffold picks, or how they behave inside a keyboard-aware Drawer.
- **The Android back gesture on a dirty form.** Refused once, then it navigates. Finanssi's owner kept it, to be revisited on a report. Hovimestari inherits the same behaviour unless designed otherwise.
- **Phone form fit.** A common finanssi entry form still overflows a 390×664 screen by 22px, and the number pad hides the next field behind the footer (finanssi `TODO.md`). The food log sheet should be measured against a 390×664 screen with the keyboard up from its first design.
- **Doc drift in finanssi.** `docs/app/mobile-responsive-shell.md` says every money input is `type="text" inputMode="decimal"` through `parseAmountInput`. The transaction amount is in fact `MinorUnitsAmountInput` with `inputMode="numeric"`. Read the code, not that line, when lifting.
